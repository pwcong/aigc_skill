# 提示词与交付格式

## 处理模式与交付范围

先读取 SKILL.md 的执行前确认规则。尚无明确选择时，先询问并等待；不自行默认分割，不预先生成正式提示词或分段产物。以下编号 MP4 和逐段提示词流程适用于已确认的 split 模式。whole 模式使用完整原视频作为 @视频1，生成一份 `完整提示词.txt`，按整片从 0 秒起描述所有原镜头，保留内部切镜；不创建短片，也不因为未导出短片而标记失败。

用户同一任务中已有明确选择则沿用，不重复确认。指南应注明本次选择及依据，不将别的原片或旧项目的模式自动带入新任务。

## 素材清单

按本次原片填写，避免通用采购清单。

| 状态 | 素材或决定 | 用途与对应段落 | 现有文件或需要补充的内容 |
|---|---|---|---|
| 已有／必需／可选 | 原角色 A 对应的新角色图 | 正面特写及全身动作 | 清楚的面容与完整造型 |
| 已有／必需／可选 | 角色映射与服装策略 | 全部角色 A 出镜段 | 完整造型／仅换身份 |
| 已有／必需／可选 | 主场景图 | 主要机位 | 透视、布局、照明 |
| 已有／必需／可选 | 反打方向补图 | 原片出现反打的段落 | 仅补缺少的方向 |

“必需”应限于无法确定替换结果的真实缺项。新增多个角度常是提高稳定性的建议，不应自动成为阻止拆片和写草稿的前置条件。用户保留原背景时，背景图不是缺项。

收到图片后实际查看，建立映射表：原片身份或元素 → 稳定别名 → 文件 → @ 标签。开头绑定使用 `@视频1`、`@图片1` 等实际素材标签，后文用别名；平台标签不同或上传顺序改变时，只更新绑定区及指南中的对应关系。不要把别名、文件名或人物名冒充平台已绑定的素材。

## 集中素材绑定与正文别名

每份完整提示词以“素材绑定：”自然段开头，集中定义本次使用的参考视频、角色、环境、替换道具及其他实际提供的替换素材。同一素材的 @ 标签只写一次；后续所有段落只使用定义好的别名。总指南的映射表和 TXT 副本可重复展示绑定，不要求整个项目只出现一次 @。

- 推荐中性、稳定的别名：参考视频、角色A、角色B、主场景、道具A。用户已指定的称呼也可作为显式定义的别名；不要用当前发色、服装或图片序号作为默认别名，以免换图后失效。别名不加 @，不能写成虚构的平台标签 `@角色A`。
- split 的“参考视频”绑定当前编号短片，每次上传它都可以是 `@视频1`，不是按段号写成 `@视频13`；whole 则绑定整条原视频。正文的动作参考和计时起点均使用“参考视频”。
- 角色示例：“角色A = @图片1 中的角色”。人物对应段再用原片的明确辨识特征说明谁替换为角色A，并说明采用完整造型还是仅换身份。逐镜动作、道具归属和限制句均写角色A；连续主语可用“该角色”，互动或可能混淆时恢复完整别名。
- 同一角色有多张图时，在同一处合并绑定，例如“角色A = @图片1 中的角色，以 @图片2 补充侧面造型”；每张图仍只引用一次，并说明多图属于同一人；素材冲突时写明主参考及补充用途。不要按每张图定义多个演员。
- 一张图含多个要替换的对象时，先绑定一次共享素材，再按图中明确区域定义对象，例如“人物参考 = @图片1；角色A = 人物参考左侧人物；角色B = 人物参考右侧人物”。同图多个道具也按位置或特征区分；不要为省略 @ 丢掉身份或实例差异。
- 多机位环境可定义“场景前视 = @图片3 中的环境；场景后视 = @图片4 中的环境”，再说明“主场景由场景前视与场景后视共同确定，为同一空间”。后文使用这些已定义别名，比如“品牌墙以场景后视为准”。同一图片兼作环境和标识参考时复用已有别名及区域描述，不为不同用途重复 @。
- 需要替换且有素材的道具、标识等同样定义别名，并说明与原片元素的对应关系。不替换的原片道具照常描述，不强制新增图片或虚构绑定。前景道具和人物手中道具仍须区分实例，不能因共用外观参考而合并。
- 每份可独立复制的 TXT 都包含本段所需绑定，不依赖其他段或总指南。同一项目保留别名职责及素材映射；某段不用的素材可省略，不占用已定义别名去指另一个角色。每个别名都须能最终解析到实际素材；先定义共享素材或组成别名，再定义图中对象或组合场景，避免循环或未定义引用。
- 指南对照表至少含：别名、@ 标签、实际文件、素材用途、是否已提供。没有素材时可在草稿绑定区预留标签并列出缺项；不能虚构文件存在。目标外观以绑定素材为准，只另写用户要求锁定的细节，不把旧颜色、发型或品牌写进正文影响换图。

@ 标签是绑定区中的有效素材引用，**不是应删掉的未完成占位符**。素材和角色映射齐备、正文完整、所有别名均可解析时，可标为就绪；用户仍需按指南上传并绑定标签。缺图、角色对应不明、未填时间或未知动作的版本仍是草稿。别名只是自然语言指代，不意味着已经执行平台绑定。

更换同一职责的素材或上传标签时，集中修改开头绑定和指南映射；正文别名与原片动作、机位、时间保持稳定。若用户改变角色职责、替换范围或明确锁定的外观要求，再同步相关语义，不能承诺任何素材更换都完全无需调整正文。

## 精确分段计划

可用下面的结构存储计划，字段可扩展；不要把示例数据当成用户原片参数。例子只有一段，时间单位为 1/90000 秒：

```json
{
  "schema_version": 1,
  "processing_mode": "split",
  "mode_confirmation": {"confirmed": true, "basis": "<本次用户的明确选择或同一任务已确认要求>"},
  "source": {
    "file": "../source.mp4",
    "sha256": "<从实际文件计算>",
    "time_base": "1/90000",
    "video_start_tick": 0,
    "video_end_tick": 90000,
    "fps": "30000/1001",
    "timing_mode": "pts",
    "display_size": [1920, 1080]
  },
  "status": "draft",
  "segments": [
    {
      "id": "01",
      "title": "按实际内容命名",
      "start_tick": 0,
      "end_tick": 90000,
      "reference_video": "分镜参考视频/01.mp4",
      "export_status": "pending",
      "prompt": "分镜提示词/01_内容.txt",
      "prompt_status": "draft",
      "shots": [
        {
          "local_start_tick": 0,
          "local_end_tick": 90000,
          "transition_in": "segment_start",
          "description": "<核对画面后填写>",
          "verified": false
        }
      ]
    }
  ]
}
```

字段语义：
- `processing_mode` 为用户已明确选择的 split 或 whole，`mode_confirmation` 记录选择依据，不能因为本示例默认写了 split 就替用户选择。未确认时不执行本计划。
- 上面的示例用于 split。whole 模式可在 `处理计划.json` 中仅保留一个覆盖整片的参考单元，`reference_video` 指向实际原视频，`prompt` 为 `完整提示词.txt`，`export_status` 为 `not_required`；镜头列表仍保留原片内部切镜。原视频起始 PTS 非零时，正文镜头时间统一减去该起点，使整片从 0 秒计时。
- tick × time_base = 精确秒数。使用实际媒体时间基，不为套示例强改为 90000。
- segment 的 start/end 是源片全局时间；shot 的 local_start/end 相对于所属段开头。
- 若同时记录帧号，采用从 0 开始的显示顺序帧号，不含终点帧。可变帧率不能由平均 fps 换算帧号。
- `transition_in` 说明硬切、叠化、淡入或连续长镜头的段首；不要默认全是硬切。
- split 模式的 `export_status` 按实际进度记录为 pending、verified 或 failed；已有参考短片复核通过可标记 verified，并注明复用。whole 模式统一记为 not_required。`prompt_status` 独立记录 draft 或 ready。角色素材缺失时可以是视频已 verified、提示词仍 draft。
- `status=ready` 要求处理模式已确认，引用对照、映射、素材及动作核对完成，并且 split 模式的全部目标参考片段核验通过，或 whole 模式的原视频可正常使用。此状态不要求已上传平台；开头绑定区应保留供用户使用的 @ 标签，正文别名均应有定义。资料缺失时列出缺项并保留 draft。用户明确不需要参考视频时另行记录范围例外，不伪造导出状态。
- 计划中保存的素材路径相对于计划文件解析，写入后逐个确认存在。计算相对路径前先解析两端真实路径，避免 /tmp 等符号链接导致 ../ 指错目录；也可保存经核验的绝对路径。人类交付链接使用当前实际可用路径。

把精确计划转成人类时间表，至少展示：编号、原片起止、有效时长、镜头数、局部切点、动作概要、参考片段、提示词。平台档位已知时才增加生成时长列。整数 fps 的“分:秒:帧”与十进制秒不要混用；分数帧率需注明制式，或直接展示秒数和精确边界。

## 参考视频与提示词的对应表

split 模式除完整指南外，交付 `视频与提示词对照.md`，让用户按编号拿到实际参考短片。每一行对应一个生成片段，不是一个原片内部镜头。whole 模式用一行关联完整原视频和 `完整提示词.txt`，注明“不分割，复用原视频”，不伪造 01.mp4 或短片导出状态。

| 编号 | 原片全局范围 | 参考短片实际时长 | 原片参考 MP4 | 完整提示词 TXT | 视频核验 / 提示词状态 |
|---|---|---|---|---|---|
| 01 | 按已核实区间填写 | 读取导出文件 | 链接到实际 01.mp4 | 链接到同编号 TXT | 已核验 / 就绪或草稿 |

链接必须可打开，时长来自实际文件核验。视频可用但提示词缺素材时，把两个状态分开写，照常链接参考文件。split 模式表上说明：生成第 01 段时只上传 01.mp4 作为当前 `@视频1` 并复制 01 的完整提示词，其他段依次对应。whole 模式则说明上传整条原视频作为 `@视频1` 并复制整片提示词。两种模式都不把已替换人物的生成结果当成原片参考。

## 每段完整提示词模板

使用以下**连续自然段格式**，依次为：素材绑定 → 视频用途 → 人物对应固定 → 场景参考 → 镜头与互动规则 → 输出要求 → “本段重点：” → 逐镜局部时间段 → 本段易错限制 → “时间要求：”。正文不改成表格、JSON、提纲式字段清单，不添加 YAML、Markdown 标题或复制说明；这些管理信息放在指南里。总指南的代码块可以包裹 TXT 全文，但 TXT 文件本身不含代码围栏。

下列结构自包含，不依赖原项目文件，适用于两种模式。split 模式逐段使用；whole 模式把“当前片段／本段”按语义改为“完整原视频／本视频”，重点标题使用“本视频重点：”，整片写在一个 TXT 内，时间从整片开头计算，内部切镜不变。示例中的两名角色和一张场景图仅用于展示格式；根据实际素材增减，不强制两人或固定场景图数量。成品填好所有尖括号内容，只在开头绑定区保留实际采用的 @ 引用；正文不再重复标签。时间段首行使用“0.000–1.767 秒：描述”这样的写法，段落间留空行。

```text
素材绑定：参考视频 = @视频1；角色A = @图片1 中的角色；角色B = @图片2 中的角色；主场景 = @图片3 中的环境。

以参考视频为当前片段的动作和镜头参考，只替换<用户指定的人物与环境范围>，保留这个片段的原有镜头顺序和动作节奏。

人物对应固定：参考视频中的<原角色 A 的明确外观或身份标识>替换为角色A；参考视频中的<原角色 B 的明确外观或身份标识>替换为角色B。<按用户选择写完整造型或仅换身份：例如两人的面容、发型、服装、配饰和鞋子分别以角色A、角色B绑定的素材为准。><仅当图片为多视图时，说明各视角展示的是同一个人。>只在原片对应角色实际出镜的位置进行替换，不强制所有角色同时入镜。

场景使用主场景，<写明该场景与原镜头之间的空间、机位和互动关系；有其他视角素材时在开头先绑定，并在这里使用其别名补充方位与优先级。><如需固定品牌标识，引用对应场景或标识别名及图中区域，说明位置随机位自然产生透视。>场景素材用于空间和外观参考，不生成拼图或分屏，不为展示参考素材中的物品额外改变构图。

保留参考视频的景别、视角、构图、景深、运镜、人物站位及前后遮挡。<按原片说明真实切镜或转场；不要默认全为硬切。>同一镜头内的推拉、绕拍、转焦或人物转身连续完成。快速动作的中间过程继续跟随参考视频，不跳过或另编动作。只保留本段实际出现的互动道具和特效，保持手与道具的接触及归属、脚部着地或离地的状态；被遮挡的手和道具沿用原片轨迹，不擅自添加递交、换手或肢体接触。

输出<经原片核对或用户指定的画幅与质感>，保持参考视频的动作节奏。<仅写适用于当前任务的输出限制。>

本段重点：
本段保留参考视频中的 <N> 个镜头，以下时间均从参考视频的开头计算。<用角色A、角色B等已定义别名概括本段实际出镜顺序及重点。>

0.000–<第一切点> 秒：<景别与机位>，角色A<在画面中的位置与起始姿态>。先<动作一>，随后<动作二>，最后<结束姿态>；<写清前后景道具、持握接触、脚部承重、连续运镜和特效时点。><本镜有实际风险时补一句针对性限制。>

<第一切点>–<下一切点或结束> 秒：<真实切镜或转场方式>到角色B<对应构图>。<依次写起始、动作和结束；涉及参考场景或替换道具时也使用开头定义的相应别名。>

<按实际镜头数增减时间段；补充本段整体易错限制，仍使用已定义别名，不混入未定义称呼或素材编号。>

时间要求：
参考视频的有效时长为 <D> 秒。以上时间均为本段内的局部时间，从 0 秒起算。按照这些时间完成全部动作与原有切镜，保持原片动作速度，不把动作均匀拉伸到更长的生成时长。<生成档位已知且 G 大于 D 时：若生成设置为 G 秒，则在前 D 秒完成本段内容，多出的时间只延续末尾姿态作短暂停留，不新增动作、切镜或剧情。若 G 等于 D 则写按 D 秒结束；未知时不猜档位。>
```

## 逐镜描述的精度示例

弱描述：“人物靠近，抬腿，最后是道具特写。”

可执行描述应依据实际视频落到如下程度：“角色A先在低机位近景抬起持道具的手，形成手大、脸在后方的透视；下一镜才抬膝、停顿、落脚和短距离前移。最后切极近前景道具，先对焦前景，再转焦到正在靠近的后景人物。前景道具与人物手中的道具各自保持独立。”

这里的角色A已在开头绑定。这是描述精度的例子，不是通用剧情。时间、道具数量、运动方向、连续或切镜关系都必须来自新原片。不能将这一动作复制给别的视频。

每条限制应解决本段的实际歧义，例如：
- 原片只有抬手时，限制额外走向镜头。
- 前后景有两个道具时，限制合并、变形或凭空递交。
- 倒地从低姿开始时，说明不先站起再倒。
- 飞散物只在末尾出现时，注明起始时间，不扩成全段特效。

## 操作指南与最后核对

总指南包含：
1. 用户已确认的处理方式及依据；split 模式列已导出的参考短片目录和逐段对照，whole 模式列原视频和整片提示词链接。两种模式都附镜头时间表及正确的上传、引用说明。
2. 素材上传顺序、别名与文件及 @ 标签映射；说明每份 TXT 只需在开头绑定区替换标签，后续动作、场景和限制沿用别名。
3. 已核实的平台设置；未指定平台时用通用“视频＋图片参考”流程，不指定未经核实的按钮或模型。
4. 每段可独立复制的完整正文，与 TXT 完全一致。
5. 生成后如何比较原切点、动作顺序、造型、接触、遮挡和特效；只重做有问题的段落。
6. 后续剪辑需要区分“末尾多余停留”与“动作被整体拉长”。只对前者直接去尾；后者应按镜头对齐或重做。

split 模式先对精确计划检查相邻段 end=start、首尾覆盖范围、段内镜头连续覆盖，再对照导出文件检查媒体时长和首尾帧。whole 模式核对原视频链接、整片镜头时间的覆盖及一份提示词的完整性，不要求导出文件。秒数三位小数是展示值，不能据此判断是否差一帧。比较各 TXT 与总指南对应代码块，确保全文一致；不能只比文件标题。另查每份 TXT 的 @ 标签是否仅在开头绑定区出现且每个素材只出现一次；正文别名全部有定义、含义稳定，与原角色及文件映射一致，没有散落的 @ 标签或“图片1”等编号引用。多视图不新增演员、同一素材多用途不重复绑定；检查更换开头标签后正文仍能正确指代。不要把参考格式中的具体人物名或固定图片数量带入新任务。
